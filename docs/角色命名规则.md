# 角色命名规则

小说生成器和三个角色图片仓库（[character-image-staging](https://github.com/cjhkcjgk3-sys/character-image-staging)、[character-image-staging-2](https://github.com/cjhkcjgk3-sys/character-image-staging-2)、[character-image-staging-azurlane](https://github.com/cjhkcjgk3-sys/character-image-staging-azurlane)）用同一套命名规则。图片仓库里的说法见各仓库《图片收集通用经验》第五节，两边改动要同步。

**命名模型：作品名（前缀）＋ 角色名 ＋（后缀）。**

| 部分           | 写法                                       | 说明                                                                                                                |
| -------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 作品名（前缀） | `崩坏三`、`碧蓝`                           | 只在小说角色名单里可选地写；图片文件名和清单不写，作品文件夹已经表示作品。可用的作品名来自清单标题和 `作品别名：`。 |
| 角色名         | `亚瑟`，不写 `亚瑟·潘德拉贡`               | 取最常见的简短名。同一作品里不得重名：简称会和别的角色撞名时（如绝区零 `安比` 与 `零号·安比`），保留能区分的写法。  |
| 后缀           | `（亡灵骑士）`、`（改造）`、`（雷之律者）` | 这张立绘的形态、装甲或皮肤名，写在全角括号里；本体立绘不写后缀。                                                    |

例子：`亚瑟（亡灵骑士）`；`拉菲`、`拉菲（改造）`；崩坏3 文件夹里的 `雷电芽衣（雷之律者）`、`雷电芽衣（始源之律者）`。小说角色名单里写 `崩坏三雷电芽衣（雷之律者）`、`雷电芽衣雷之律者` 也能对上同一张图。

**同一作品里，每个形态只用一种固定的后缀写法**：统一写 `改造`，就不要有时写 `改`。插件对后缀逐字比较（只忽略括号样式、标点和空格），`拉菲改` 对不上 `拉菲（改造）`。最省事的做法是在小说生成器里用“📋 从清单添加到名单”，名字原样复制自清单，和图片名天然一致；手写名单时照抄清单写法。这套规则的目的是尽量减少对不上的情况，不追求覆盖所有写法。

## 插件怎么匹配

按顺序比较：① 完整名称；② 去掉作品名后的“角色名＋后缀”；③ 没有后缀时只比角色名（含清单别名，本体的别名也适用于它的形态图）。只忽略全／半角、括号样式、标点、空格和间隔号，所以 `长门·META` 和 `长门（META）` 等价。写了后缀但没有对应形态图时按无图处理，不用本体图顶替；不做包含或模糊匹配；有多张候选时不用图并提示原因。实现见 `src/novel/roleImageLibrary.js`，细节见 [同楼层批量写卡](same-floor-role-batch.md)。
