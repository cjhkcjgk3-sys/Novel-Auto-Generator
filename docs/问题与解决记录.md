### 名字逐字相同才匹配，太死板（1.14.0，2026-11-14）

- 现象：v1 要求名单名与图片名完整逐字相同，`安比（绝区零）改` 这类写法找不到图。
- 解法：名单名 =［作品名，可选］+ 角色名 +［备注，可选］。先比完整名称，再去掉作品名比“角色名＋备注”，没有备注只比角色名；只忽略全／半角、括号、标点、空格和间隔号。实现见 `src/novel/roleImageLibrary.js` 的 `parseRoleImageName`、`matchRoleImage`。

### 备注要严格，不能为了“找到图”放宽（1.14.0，2026-11-14）

- 现象：如果做包含匹配，`拉菲改` 会顶替成本体图 `拉菲`，`小安比` 会配到 `安比`。
- 解法：写了备注但没有对应形态图就按无图，不用本体图；不做包含或模糊匹配；多候选不用图并提示原因。备注写法要和图片名一致：`拉菲改造` 能对上 `拉菲（改造）`，`拉菲改` 对不上。括号样式不影响（`长门·META`、`长门（META）` 等价）。

### 清单在 ZIP 根目录时导入失败（1.14.0，2026-11-14）

- 现象：用 download-directory 直接打包的作品 ZIP，`00-清单.md` 在根目录，旧版只认作品子目录。
- 解法：根目录、一层、两层作品目录都支持；作品名依次取清单标题“# X角色图片清单”、作品目录名、作品别名、ZIP 文件名；忽略 `__MACOSX`。

### 中文 Windows 压缩的 ZIP 文件名乱码（1.14.0，2026-11-14）

- 现象：文件名是 GBK 编码，按 UTF-8 解出来是乱码，图片对不上名字。
- 解法：有 UTF-8 标记按 UTF-8；否则先严格按 UTF-8 解码，失败再按 GBK。

### 整包读进内存，大作品导入占用过高（1.14.0，2026-11-14）

- 现象：明日方舟 259 MB 包导入峰值约 661 MB，碧蓝 356 MB 包约 808 MB，手机上有风险。
- 解法：导入时只读 ZIP 目录，逐张用 `DecompressionStream` 解压、生成约 128 px 缩略图、上传后释放；峰值降到约 141 MB／100 MB。浏览器不支持时回退到酒馆 JSZip（整包载入），Safari 16.4 以下属于这种情况。

### 新界面和插件风格不一致（1.15.1，2026-11-14）

- 现象：浏览器默认蓝色勾选框、暗色主题下看不见的虚线框、黑底上看不清的按钮。
- 解法：直接用插件已有类名和颜色（见开发准则「UI 一致性」），在 390 px 宽、暗色主题下截图自查。

### 图片没有发给模型（2026-11-14）

- 现象：有图但模型像没看到。
- 原因：酒馆「发送内嵌媒体 / Send inline images」关闭时，酒馆会静默丢掉图片。
- 解法：先让用户确认该开关已打开，再查插件。

### `npm run verify` 里有 3 项既有失败（2026-11-14）

- 现象：`tests/host/sillyTavern.test.js` 2 项、`tests/novel/roleWorldbook.test.js` 1 项失败（2026-11-14 为 518 通过、3 失败）。
- 说明：1.14.0 之前就存在，与图片库无关；不要为此排查半天。汇报时说明“既有失败未变、无新增失败”，修复它们另开任务。

### 名称匹配组合测试（2026-11-14，部分未解决）

用 `node scripts/name-match-matrix.mjs` 跑组合测试（只读，不改插件）：真实清单（绝区零、明日方舟、星穹铁道、原神、FGO、碧蓝航线、蔚蓝档案、妮姬、尘白禁区）每张图用自己名字的约 13 种写法回查，加上合成用例，共 27,551 条，无异常。以后改匹配逻辑先跑一遍。

**错图（最严重，待修）**

- 混合作品文件夹里写错游戏名：只有 `最终幻想7蒂法` 时，`最终幻想8蒂法`、`蒂法（最终幻想8）` 都配到它。原因：`parseRoleImageName` 把所有作品别名都当作可去掉的前缀或括号内容，不核对名单和图片名里的作品名是否相同。建议：两边都带作品名且不同，就按无图处理；名单不写作品名时保持现状。
- 作品名恰好是另一个名字的开头时会被误去掉（合成例：作品名 `空`，名单 `空荧` 去掉 `空` 后配到 `荧`）。现有 23 个清单里没有这种情况，暂不处理。建议：去掉作品名前缀后若完整名称本身就是某个角色，优先按完整名称处理。

**过严、合理写法配不到图（低）**

- 多个后缀顺序不同：`白子（幼女·泳装）` 配不到 `白子（泳装·幼女）`；作品名插在两个后缀中间（`贞德〔Alter〕（FGO）Berserker`）也配不到。建议：多个备注可按集合比较；或者保持现状，从清单添加名单即可避开。
- 后缀写在角色名前面且不加括号：`泳装白子` 配不到 `白子（泳装）`（写成 `（泳装）白子` 或在清单别名里写 `泳装白子` 可以）。按设计保留，避免误配。
- 只有形态图、没有本体图时，只写角色名（`雷电芽衣`、`绊爱`）无图。按设计保留。
- 繁体（`長門`）不会转简体。清单统一用简体，暂不处理。
- 全名与短名不一致是数据问题：`布洛妮娅（理之律者）` 配不到 `布洛妮娅·扎伊切克（理之律者）`，靠清单改名或写别名解决。

**表现正常的写法**：全／半角括号、〔〕【】「」等括号样式、`·` 与空格、大小写、全角字母数字（`ＳＡＢＥＲ`、`Ｕ－５５６`）、作品名前缀／`作品·名`／`【作品】名`／`名（作品）`／作品别名、`长门·META` 与 `长门（META）` 互通、本体别名作用到形态图（`影（冬日）`）、`零号·安比` 与 `安比`、`凯尔希` 与 `凯尔希·思衡托` 互不串、`拉菲改` 不配 `拉菲（改造）`、同名或共用别名时报歧义不用图、空串／只有括号／超长名字／表情符号都不报错。
