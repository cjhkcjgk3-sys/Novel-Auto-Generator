### 角色卡默认只用本体立绘，皮肤当作服装（2026-11-14）

- 现象：图片仓库原先“挑着收皮肤、每个角色一两套”的规则，和生成角色卡默认只带本体立绘的用法不一致。
- 解法：文档改为与现有插件行为对齐。从清单添加到名单时，皮肤在单独折叠分组里，勾选框默认不勾（`checklistSelection` 初始为空，全选按钮只管本体区）；匹配时皮肤名带后缀，名单只写 `拉菲` 不会配到 `拉菲（泳装）`。本次只改文档，未改代码。图片仓库同步改为“默认不收皮肤，点名某作品才收，要收就全收”。

### 名字逐字相同才匹配，太死板（1.14.0，2026-11-14）

- 现象：v1 要求名单名与图片名完整逐字相同，`安比（绝区零）改` 这类写法找不到图。
- 解法：名单名 =［作品名，可选］+ 角色名 +［备注，可选］。先比完整名称，再去掉作品名比“角色名＋备注”，没有备注只比角色名；只忽略全／半角、括号、标点、空格和间隔号。实现见 `src/novel/roleImageLibrary.js` 的 `parseRoleImageName`、`matchRoleImage`。

### 备注要严格，不能为了“找到图”放宽（1.14.0，2026-11-14）

- 现象：如果做包含匹配，`拉菲改` 会顶替成本体图 `拉菲`，`小安比` 会配到 `安比`。
- 解法：写了备注但没有对应形态图就按无图，不用本体图；不做包含或模糊匹配；多候选不用图并提示原因。备注写法要和图片名一致：`拉菲改造` 能对上 `拉菲（改造）`，`拉菲改` 对不上。括号样式不影响（`长门·META`、`长门（META）` 等价）。

### 清单在 ZIP 根目录时导入失败（1.14.0，2026-11-14）

- 现象：用 download-directory 直接打包的作品 ZIP，`00-清单.md` 在根目录，旧版只认作品子目录。
- 解法：根目录、一层、两层作品目录都支持；作品名依次取清单标题“# X角色图片清单”、作品目录名、作品别名、ZIP 文件名；忽略 `__MACOSX`。

### 中文 Windows 压缩的 ZIP 文件名乱码（1.14.0，2026-11-14）

- 现象：文件名是 GBK 编码，按 UTF-8 解出来是乱码，图片对不上名字。
- 解法：有 UTF-8 标记按 UTF-8；否则先严格按 UTF-8 解码，失败再按 GBK。

### 整包读进内存，大作品导入占用过高（1.14.0，2026-11-14）

- 现象：明日方舟 259 MB 包导入峰值约 661 MB，碧蓝 356 MB 包约 808 MB，手机上有风险。
- 解法：导入时只读 ZIP 目录，逐张用 `DecompressionStream` 解压、生成约 128 px 缩略图、上传后释放；峰值降到约 141 MB／100 MB。浏览器不支持时回退到酒馆 JSZip（整包载入），Safari 16.4 以下属于这种情况。

### 新界面和插件风格不一致（1.15.1，2026-11-14）

- 现象：浏览器默认蓝色勾选框、暗色主题下看不见的虚线框、黑底上看不清的按钮。
- 解法：直接用插件已有类名和颜色（见开发准则「UI 一致性」），在 390 px 宽、暗色主题下截图自查。

### 图片没有发给模型（2026-11-14，1.15.3 起会提示）

- 现象：有图但模型像没看到。
- 原因：酒馆 `openai.js` 的 `isImageInliningSupported()` 为 false 时静默丢图：非 Chat Completion 接口、「发送内嵌图片」关闭、或当前型号不在酒馆的识图名单里。酒馆 1.19.0 的名单有 `gemini-2.0`、`gemini-2.5`、`gemini-3`、`gemma-4`，**没有 `gemini-4`**；Google AI Studio（makersuite）和 Vertex AI 来源都按这份名单判断。自定义（兼容 OpenAI）来源一律返回 true。图片文件被删时酒馆 `addImage` 也静默跳过。
- 实测（真实酒馆 1.19.0，2026-11-14）：自定义来源、Vertex `gemini-3.7-flash`、AI Studio `gemini-3.1-pro-preview` 请求里都带图（`image_url`）；Vertex 和 AI Studio 设成 `gemini-4-hydrogen` 时请求不带图，插件弹出提示。
- 解法：1.15.3 起插件直接调用酒馆的 `isImageInliningSupported()`，并用 HEAD 请求检查图片文件，不发图时每批提示一次原因，不改变酒馆的发图行为。用户要给 gemini-4 发图，可用自定义（兼容 OpenAI）来源或 OpenRouter，或等酒馆更新识图名单。

### `npm run verify` 里有 3 项既有失败（2026-11-14，1.15.3 已解决）

- 现象：`tests/host/sillyTavern.test.js` 2 项、`tests/novel/roleWorldbook.test.js` 1 项失败（2026-11-14 为 518 通过、3 失败）。

### 名称匹配组合测试（2026-11-14，第一条错图已在 1.15.2 解决）

用 `node scripts/name-match-matrix.mjs` 跑组合测试（只读，不改插件）：真实清单（绝区零、明日方舟、星穹铁道、原神、FGO、碧蓝航线、蔚蓝档案、妮姬、尘白禁区）每张图用自己名字的约 13 种写法回查，加上合成用例，共 27,551 条，无异常。以后改匹配逻辑先跑一遍。

**错图**

- 已解决（1.15.2）：混合作品文件夹里写错游戏名：只有 `最终幻想7蒂法` 时，`最终幻想8蒂法`、`蒂法（最终幻想8）` 都配到它。原因：`parseRoleImageName` 把所有作品别名都当作可去掉的前缀或括号内容，不核对名单和图片名里的作品名是否相同。解决：`parseRoleImageName` 同时返回去掉的作品名（`work`），索引记下每张图带的作品名；名单和图片都带作品名、且不相等也不互为前缀时去掉该候选，全去掉则无图（原因“作品名不同”）。图片库自己的名字（清单标题）不算其他作品；名单不写作品名时不变。测试见 `tests/novel/roleImageLibrary.test.js`「mixed-work folders」，组合测试合成用例错图从 3 降到 1。
- 未解决：作品名恰好是另一个名字的开头时会被误去掉（合成例：作品名 `空`，名单 `空荧` 去掉 `空` 后配到 `荧`）。现有 23 个清单里没有这种情况，暂不处理。建议：去掉作品名前缀后若完整名称本身就是某个角色，优先按完整名称处理。

- 已解决（1.15.3）：判断同一作品原先用“一个是另一个的开头”，`最终幻想1` 与 `最终幻想10` 会被当成同一作品。现在只认写法相同或清单 `作品别名：` 里用 `=` 登记的（`最终幻想7=最终幻想7重制版`）。真实清单受影响的只有主机与PC游戏：`最终幻想7`／`最终幻想7重制版` 要用 `=` 登记才互通；`艾尔登法环`／`艾尔登法环黑夜君临`、`匹诺曹的谎言`／`序曲`、`龙腾世纪`／`审判` 本来就是不同作品，现在分开是对的。组合测试 27,958 条，合成用例错图仍只剩 `空荧` 1 条。

**过严、合理写法配不到图（低）**

- 多个后缀顺序不同：`白子（幼女·泳装）` 配不到 `白子（泳装·幼女）`；作品名插在两个后缀中间（`贞德〔Alter〕（FGO）Berserker`）也配不到。建议：多个备注可按集合比较；或者保持现状，从清单添加名单即可避开。
- 后缀写在角色名前面且不加括号：`泳装白子` 配不到 `白子（泳装）`（写成 `（泳装）白子` 或在清单别名里写 `泳装白子` 可以）。按设计保留，避免误配。
- 只有形态图、没有本体图时，只写角色名（`雷电芽衣`、`绊爱`）无图。按设计保留。
- 繁体（`長門`）不会转简体。清单统一用简体，暂不处理。
- 全名与短名不一致是数据问题：`布洛妮娅（理之律者）` 配不到 `布洛妮娅·扎伊切克（理之律者）`，靠清单改名或写别名解决。

**表现正常的写法**：全／半角括号、〔〕【】「」等括号样式、`·` 与空格、大小写、全角字母数字（`ＳＡＢＥＲ`、`Ｕ－５５６`）、作品名前缀／`作品·名`／`【作品】名`／`名（作品）`／作品别名、`长门·META` 与 `长门（META）` 互通、本体别名作用到形态图（`影（冬日）`）、`零号·安比` 与 `安比`、`凯尔希` 与 `凯尔希·思衡托` 互不串、`拉菲改` 不配 `拉菲（改造）`、同名或共用别名时报歧义不用图、空串／只有括号／超长名字／表情符号都不报错。

### 角色生成兼容性核查（2026-11-14，1.15.2，未改代码）

范围：同楼层批量写卡、角色名单、图片库、从清单添加、角色世界书导入导出、设置迁移。txt 转世界书、自动续写不在范围内。方法：读代码；Vitest；在盒子上起真实 SillyTavern 1.19.0（tag `7e8663c`）和 1.13.2，用 Playwright + Chrome 实际操作，模型回复用合成响应（见下一条）。

**确认的问题**

1. 【严重，1.13.0 起；用户用 1.19，不改代码，1.15.3 README 最低版本改为 1.14.0】酒馆 1.14.0 以下插件整个加载不了。`src/host/runtime.js` 静态 `import { MEDIA_DISPLAY, MEDIA_SOURCE, MEDIA_TYPE } from '/scripts/constants.js'`，这三个导出 1.14.0 才有。实测 1.13.2：报 `The requested module '/scripts/constants.js' does not provide an export named 'MEDIA_DISPLAY'`，面板不出现；同一环境装 1.12.x（`3cfe67e`）正常。README 仍写支持 1.13.2。建议：改成 `import * as constants from '/scripts/constants.js'`，缺这些常量时只关闭“发图”，其余功能照常；或把 README 最低版本改成 1.14.0。
2. 【高；用户用 Gemini，暂不处理】模型不支持图片时整批停住。酒馆对「自定义（OpenAI 兼容）」来源一律当作支持图片（`isImageInliningSupported()` 里 `CUSTOM: return true`），DeepSeek 这类纯文字模型走自定义地址也会收到 `image_url`。实测：接口对带图请求返回 400 时，第一个有图角色 3 次重试都带图、全部失败，任务停止，后面无图角色也不再生成。建议：带图请求失败（4xx）后，本角色剩余重试自动去掉图片并提示一次“模型可能不支持图片，已改为不带图”；不新增开关。
3. 【中，数据触发；1.15.3 已解决：按 zip 路径去重，重复行的名字并为别名】清单里同一张图出现两次会被导入两份，导致这个名字“多候选、无图”。`parseChecklist` 不按路径去重（例如同一行同时写在角色区和「## 皮肤」区）。实测：`安比（改）` 导入 2 张，名单 `安比（改）` 显示“有 2 张图片都对应…无法确定”，不发图；清单面板也标“无图”。现有 23 个清单扫描无重复，以后加皮肤时容易出现。建议：`parseChecklist` 按 `path` 去重，同一路径只导入一次。

**风险 / 体验问题**

4. 【中】一次只能有一个作品图片库。导入第二个作品前必须清空，而清空会删除第一个作品的图片文件；一本小说里同时有两部作品的角色时，只有一部有图。建议以后支持多个图片库（按作品分开存，匹配时合并，跨库重名按多候选处理）。
5. 【低】“这个角色不用图”记的是名单里的写法，不是图片。把 `猫又` 设为不用图后，名单写 `TestWork猫又（测试作品）` 仍然会发 `猫又` 的图（实测）。建议改为按匹配到的图片路径记录，或在提示里写明“按这一行的名字记录”。
6. 【低】导入中途关掉页面会在 `user/images/novel-auto-generator-role-images/` 留下已上传的图，图库里没有记录，“清空图片库”也删不掉。建议清空时顺带清理该文件夹里不属于当前图库的文件，或导入开始时先记下待清理清单。
7. 【低；1.15.3 已解决：从头生成后的第一批视为已核对，只问一次（刷新页面后仍可能再问一次）】“从头生成全部角色”确认后，旧批次留下的备选页会被当成“无法识别的已有角色”，再弹一次确认框，相当于连问两次。建议从头生成时把旧批次的页视为已核对。
8. 【低；1.15.3 已解决：每批一次 toastr 提示，见上方「图片没有发给模型」】酒馆关闭「发送内嵌媒体」、用文本补全（非 Chat Completion）接口、或图片文件被删掉时，都是静默不发图，生成照常成功（已实测）。行为合理，但用户不知道图没发。可在图片库摘要里提示“当前接口不会发送图片”。
9. 【很低】`downloadFile`（`src/novel/runtime.js`）创建的下载链接没有 `revokeObjectURL`，每次导出留一个小 Blob。图片库本身不用 Object URL（缩略图是酒馆文件地址），没有泄漏。
