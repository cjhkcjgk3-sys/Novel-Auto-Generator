# 角色界面规模压力测试

本次测试在 Windows、Node 22.12、系统 Chrome 157.0.8103.51 中执行，使用生产 `initNovelUI`、真实 jQuery、插件 CSS、390 × 844 视口和合成宿主。没有调用模型，没有读取用户聊天和图片。数字是多次操作的中位数，单位 ms；用于比较本机前后版本，不能直接当作用户手机的耗时。

## 测试数据与结果

每个角色均有合成图片记录，缩略图共用一个小 SVG，避免外部网络干扰。名单／名录分别为 1000／200、5000／2000、10000／10000、30000／10000。数据以唯一中文名字为主，未覆盖复杂别名和大量正文的极端分布。

| 名单／名录   | 普通刷新：原版 → 优化 | 手动纠错：原版 → 优化 | 名录删除：原版 → 优化 |
| ------------ | --------------------- | --------------------- | --------------------- |
| 1000／200    | 9.9 → 3.4             | 45.1 → 17.7           | 22.2 → 7.4            |
| 5000／2000   | 52.0 → 5.8            | 161.2 → 37.8          | 84.8 → 23.2           |
| 10000／10000 | 82.6 → 8.2            | 301.9 → 56.9          | 220.0 → 81.4          |
| 30000／10000 | 399.1 → 17.9          | 1224.0 → 161.7        | 492.1 → 83.8          |

普通刷新通过已有设置事件触发完整 `updateUI`，含强制布局；不是只测字符串拼接。纠错走实际按钮、runner、同步 localStorage 恢复日志和 UI 回调；宿主状态核对是空实现，真实酒馆可能更慢。原版连续点击 4 次“显示更多”后，角色列表为 1000 行，页面总 DOM 约 10861～13270 个；优化后角色、名录各最多 100 行，总 DOM 约 1567～1576 个。

## CPU 降速模拟

Chrome DevTools CPU throttling rate = 4，同一生产 UI 再测。降速只模拟 CPU 压力，不等同某款手机。

| 名单／名录   | 普通刷新 | 手动纠错    | 名录删除    |
| ------------ | -------- | ----------- | ----------- |
| 1000／200    | 13.8     | 80.4        | 41.9        |
| 5000／2000   | 24.6     | 135.9       | 128.7       |
| 10000／10000 | 42.8     | 281.6       | 487.0       |
| 30000／10000 | 约 100   | 约 800～860 | 约 670～700 |

仍有明显性能边界：上万条名录每次增删都会重建匹配器；手动纠错需要克隆、核对、保存整批状态。保留这些恢复和数据校验契约，未为跑分省略。后续可用性能 trace 进一步拆分名录索引、批次克隆、localStorage 与真实宿主核对的耗时，再决定是否做增量索引或持久化架构调整。

## 已验证与未验证

- Chrome 中执行了翻页、纠错模式切换、标记失败、名录增删、滚动同时刷新；断言没有页面错误或警告。
- 断言初始和翻页后列表行数有界，跨页“标记完成”修改正确原始索引，返回上一页索引正确，跨页删除移除正确名字，pagehide 后设置保存正确。
- 滚动采用 60 次 requestAnimationFrame 采样，并插入 4 次 UI 刷新。正常 CPU 下前 3 档 P95 帧间隔约 7 ms，30000 条约 21 ms；四倍降速下 10000 条 P95 约 63 ms。无头浏览器刷新率、系统调度与真实触摸滚动不同，不能据此宣称手机达到固定 FPS。
- 未验证真实酒馆的其他插件、角色卡正文渲染、独立缩略图解码、真实手机 WebView、模型请求、实际生成全过程、长时间内存泄漏。没有用合成宿主结果替代真实酒馆验收。
- 全部 540 项 Vitest、lint、类型检查、125 个运行模块的边界检查通过。Windows clone 的 CRLF 与仓库 Prettier 的 LF 要求冲突，另有 Cursor 自动生成的未跟踪 `.cursor/permissions.json` 被格式检查扫描；与本次逻辑改动无关。

## 复现

脚本依赖放在仓库外，不更改项目依赖和 lockfile 的依赖树：

```powershell
npm install --prefix F:\cursor\role-stress-tools playwright jquery --no-audit --no-fund
$env:PLAYWRIGHT_MODULE='F:\cursor\role-stress-tools\node_modules\playwright'
$env:JQUERY_PATH='F:\cursor\role-stress-tools\node_modules\jquery\dist\jquery.js'
$env:STRESS_CPU='1' # 或 4
node scripts/stress-role-ui.mjs F:\cursor\role-stress-after.json
```

可选 `STRESS_COUNT=1000/5000/10000/30000` 单独测一档；`ST_BROWSER_CHANNEL=msedge` 使用 Edge。`STRESS_RUNTIME` 指向旧版 `runtime.js` 可测基线（相对导入仍由本仓库服务）；必须保存 Git blob 原始 UTF-8 字节，不能经 Windows PowerShell 的默认重编码。`STRESS_SCREENSHOT` 指定仓库外截图路径。报告每完成一档即写入，避免长测试中断丢失全部结果。
