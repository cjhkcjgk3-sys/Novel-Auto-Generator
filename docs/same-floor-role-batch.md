# 同楼层批量写卡

基于本仓库 1.9.0 增加一个生成模式，继续使用原控制按钮、进度条和生成设置；名单状态复用 TXT 转世界书的勾叉渲染与样式。

## 操作

1. 打开萧谴写卡小助手角色卡的普通单角色聊天，角色卡及其世界书照常启用。
2. 最后一条用户消息放通用提示词，使用 `[[角色名]]` 标出替换位置，例如 `小助手生成角色：[[角色名]]。按写卡助手要求的格式输出。`。其后可以已有一条 AI 回复。
3. 原“生成设置”选择“同楼层批量生成”，原提示词框填写名单，每行一个，目标数量与名单人数取较小值。两种模式分别保存各自文本。
4. 点击开始。每轮更新原用户消息，后续结果放在同一 AI 楼层的候选回复中；已有结果保留。模板中的全部占位符都会替换。
5. 在原进度条及名单勾叉查看结果。暂停在当前角色结束后生效，停止会请求取消当前生成；未确认结束的请求不会自动重发。
6. 结束后进入角色卡的预览，加载全部设置，查看、选择并导出。需要此前提供的全部候选回复预览组件；小说导出按钮只读取当前消息页，不作为此模式的汇总出口。
7. 补某个角色时，将用户消息中的目标改回该角色再重生成。开始新批次前点重置，原始模板会恢复，已有候选回复不会删除。

## 简单规则

- 有文字且正常结束就打勾。没有最低字数、格式检查或质量判断。
- 无响应、空内容或调用失败：同一角色首次加两次重试，共三次，仍失败则打叉并停止整批。
- 明确报告的 `TOKEN_LIMIT` 错误：保留结果，打叉并继续下一名。原生酒馆若只返回文字而不暴露截断状态，按正常返回处理，不推测正文。
- 生成超时或无法确定上一次请求是否结束时，停止并保留待确认状态，避免重复发送；用户核对聊天后手动补或重置。
- 名单顺序和重复名字均保留。批次开始后锁定名单及模板；重试不占下一名的名额。
- 使用原生生成流程保留当前角色卡、世界书和预设。重生成时排除整个结果楼层，名单本身不发送给模型。
- 当前模式只适配单角色聊天，拒绝群聊及目标后有多条消息的情况；切换聊天后停止写入。

## 配套预览组件

配套局部正则在此前“全部候选回复预览”基础上增加：导出角色条目时自动填入姓名和已有 `nicknames`、`aliases` 或“别名”；没有别名至少保留姓名。角色条目默认常驻，可用用户已有工具批量切换开关和开启方式。

预览仅收集符合写卡助手原协议的结果；这些协议由角色卡提供，插件不另写一套格式。

## 验证与范围

- 基线：原仓库 30 个测试文件、314 项测试通过。
- 新增顺序替换、三次尝试、截断分支、暂停恢复、重复开始、切换聊天、固定楼层和候选页保存等回归。
- `npm run verify` 检查 lint、格式、类型、模块边界和全部测试。
- `scripts/smoke-role-batch.mjs` 在隔离本地酒馆中验证三个候选回复、固定楼层、实际请求保留角色卡及世界书、排除先前结果。模型响应为拦截的合成数据，不消耗模型额度。
- 2026-11-02：隔离 SillyTavern 1.18.0、Chromium 153 验收通过。导入所提供写卡助手的测试副本，原生生成三个角色时保持三层、三个候选回复；三个请求均保留角色卡及绑定世界书提示词，均不含先前生成结果。追加空响应场景恰好调用三次后停止，下一名未执行。
- 配套预览组件通过 15 项离线交互／导出检查及关键词样本核对；默认常驻，姓名与已有别名均写入关键词。该组件尚未在已安装酒馆助手的真实消息 iframe 中联动验收。
- 用户当前酒馆、实际供应商和真实模型写作质量仍需用户试用。上述宿主测试使用固定响应，不代表供应商质量验证。

复跑宿主脚本时，先启动安装本插件的隔离酒馆，在已有 Playwright 浏览器环境中运行：

```bash
ST_TEST_URL=http://127.0.0.1:18019 node scripts/smoke-role-batch.mjs
```

可用 `SMOKE_CARD` 指定本地写卡助手 JSON，在测试副本中导入并核对角色卡和世界书提示词。脚本只接受本地回环地址，不操作远程酒馆。
