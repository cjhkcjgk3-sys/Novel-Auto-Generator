# 同楼层批量写卡

基于本仓库 1.9.0 增加一个生成模式，继续使用原控制按钮、进度条和生成设置；名单状态复用 TXT 转世界书的勾叉渲染与样式。

## 操作

1. 打开萧谴写卡小助手角色卡的普通单角色聊天，角色卡及其世界书照常启用。
2. 最后一条用户消息放通用提示词，使用 `[[角色名]]` 标出替换位置，例如 `小助手生成角色：[[角色名]]。按写卡助手要求的格式输出。`。其后可以已有一条 AI 回复。
3. 原“生成设置”选择“同楼层批量生成”，原提示词框填写名单，每行一个完整名称；同名去重，角色总数自动计算。两种模式分别保存各自文本。
4. 点击“开始／继续”。已有任务会先核对完成记录并跳过已完成角色，每轮更新原用户消息，后续结果放在同一 AI 楼层的候选回复中；已有结果保留。模板中的全部占位符都会替换。
5. 在原进度条及名单勾叉查看结果。暂停在当前角色结束后生效，停止会请求取消当前生成；重新开始前先核对上一轮已保存的结果。
6. 已有角色世界书可从原导出区域导入，已有角色在备选页及名单中显示成功；补充名单后继续生成。结束后用“世界书 JSON”导出全部成功成果；角色卡自带的预览与导出仍可继续使用。TXT 导出沿用原有楼层导出方式。
7. 批次完成或明确失败停止后自动恢复原始模板。意外中断后回到同一聊天，点“开始／继续”补齐；“重置（保留已完成）”只恢复运行状态。要全部重做，点击“从头生成”并确认；已有候选回复不会删除。

### 世界书接续规则（1.10.0）

- 一个命名条目对应一个角色，名称读取条目标题，缺少标题时读取明确名称或首个关键词；导入前请与名单使用相同完整名称。支持 ST 世界书对象／数组条目及角色卡中的 character_book 格式，复用既有字段转换。
- 同名角色只建立一个任务，已有成功结果优先保留；失败或未完成项可以由导入成果补齐。重复导入不覆盖已有成功正文。旧版同名任务保留候选原文，合并为一个当前任务，其余记录保存在既有历史中。
- 有名称和有效正文的导入角色按已有成品接收，不套用当前生成的字数或闭合标签要求；空白或未命名条目汇总提示。明确属于世界观、地点、物品、规则等分类的条目保留用于导出，不进入角色名单。
- 原正文和条目配置保存在原生聊天／候选数据中；任务进度继续使用原来的 roleBatch 及恢复日志，未另建正文数据库。原书书级字段保留，新增角色由已有世界书格式化工具输出。导入本身不调用模型，不更改世界书绑定。
- 生成期间先停止再导入；导入／导出进行时禁用相应操作。导入保存或恢复日志写入失败时回退原名单与候选。JSON 无效、条目无法使用、聊天不符或缺少原生接口时给出错误，并沿用现有错误日志。
- 原生接口验证基于隔离 SillyTavern 1.18.0 源码（51ad27f）：getContext().addOneMessage、updateMessageBlock、saveChat，以及既有原生 swipe。用户设备版本仍以运行能力检查为准。
- 验证：381 项自动测试及工程检查通过；隔离酒馆完成导入、去重、3 次新增请求、刷新／重置续接、原配置合并导出及窄屏布局。原控制链 19 次合成请求断言通过。额外酒馆助手前端矩阵受其外部初始化请求失败影响未完成，不计作本次兼容验收。

### 重生成预览确认（1.11.0）

- “生成设置”新增“重生成后手动确认”，默认开启。开启时“↻ 重生成此角色”只把新回复作为候选版本追加到结果楼层末尾，原角色页、名单状态和导出内容都不改变。
- 候选页的操作栏显示“✓ 用这版替换”“↻ 再生成一版”“✗ 放弃”。“再生成一版”继续在末尾追加候选，数量不限，可左右翻页比较。
- “用这版替换”只采用当前显示的候选页：放回原角色所在位置，沿用原有保存核对、重试、完整性检测及隔离校验码，并删除其他候选页；未翻到候选页时按钮不可用并提示。“放弃”删除全部候选并回到原角色页。
- 对被完整性检测判为不合格、但生成正常结束的候选，用户确认采用后将其标为手动完成；明确中断或停止的候选不能采用。切换聊天或原有备选页在确认期间发生变化时停止写入，需重新核对。
- 待确认状态随任务一起保存到设置和恢复日志，刷新页面后仍显示上述按钮。待确认期间开始／继续、导入世界书、手动纠错、重置以及重生成其他角色都会被拒绝并提示先确认或放弃。
- 候选页带有临时标记，名单核对、导出和角色绑定都不会把它当作角色成果。用户手动删除全部候选页后，待确认状态自动结束；原有备选页被修改或楼层被删改时拒绝替换并提示，不覆盖用户内容。
- 关闭该选项即恢复 1.10.7 的行为：生成完成并确认保存后直接替换原角色页。
- 验证：以模拟 SillyTavern 1.19.0 换页、流式与保存行为的测试覆盖候选不提交、再生成追加、替换所选并清理、放弃恢复、关闭开关恢复旧行为、刷新后继续确认、手动删除候选及隔离校验。尚未在真实酒馆与实际模型服务上复验，移动端布局未检查。

## 简单规则

- 有文字且正常结束就打勾。没有最低字数、格式检查或质量判断。
- 无响应、空内容、宿主临时占位内容 `...` 或调用失败：同一角色首次加两次重试，共三次，仍失败则打叉并停止整批。重试恢复原候选页，保留此前成品。
- 明确报告的 `TOKEN_LIMIT` 错误或流式中断状态且已有正文：保留结果，打叉并继续下一名。没有正文仍按三次尝试处理。酒馆若只返回文字而不暴露截断状态，按正常返回处理，不推测正文。
- 生成超时或无法确定上一次请求是否结束时，停止并保留待确认状态。点击继续时，先等待宿主空闲并核对候选页完成标记；已保存成品补记完成，未完成则只重做该角色。
- 名单顺序和重复名字均保留。运行期间锁定名单及模板；停止后修改名单并离开输入框，勾叉列表及进度即按新名单同步，按原名称和同名出现次序继承完成记录，增加、移除或调整未完成项不会清除已有成品。改名视为新目标，重试不占下一名的名额。
- 使用原生生成流程保留当前角色卡、世界书和预设。重生成时排除整个结果楼层，名单本身不发送给模型。
- 当前模式只适配单角色聊天，拒绝群聊及目标后有多条消息的情况；切换聊天后停止写入。

## 恢复范围

复用原恢复存储的同步写入方式，保存同一份批次记录：模板、名单、条目身份、完成状态及回复位置，不重复存储生成正文或 API 配置。派发前保存待确认项，酒馆正常结束时在候选回复附加完成标记；恢复先核对聊天中实际保留的标记，再决定跳过还是补生成。

同一浏览器返回原聊天后点击“开始／继续”，不会在打开页面时自动调用模型。切后台仍受手机和浏览器调度影响；此功能负责恢复任务，不承诺后台一直运行。未保存或被截断的当前角色会重新生成，先前成品保留。清除浏览器数据、跨浏览器或跨设备不在本地恢复保证内；没有插件任务记录的手工成品不会按正文猜测归属。

旧版批次可沿用已记录的成功回复位置；升级前中断且没有完成标记的当前项会重新生成。修改名单时已移除条目的记录暂存于同一批次，重新加回同名项可继续复用；只有确认“从头生成”才清除这批完成记录。

## 错误日志

原控制区提供“下载错误日志”和“清空错误日志”，不另开窗口。仅保存最近 100 条生成失败记录：错误时间、插件版本、失败阶段、错误代码／信息、重试次数、角色序号、楼层和候选页索引，以及必要的代码位置。正常生成、轮询和手动停止不记入日志。

沿用插件设置保存，刷新和重置任务后保留，只有点击“清空错误日志”才清除。下载为 JSON 文件；不导出提示词、生成正文、请求对象、完整配置或 API Key，错误信息中的网址和常见凭据字段会过滤。若还有故障，下载这份文件提供给维护者即可。

## 配套预览组件

配套局部正则在此前“全部候选回复预览”基础上增加：导出角色条目时自动填入姓名和已有 `nicknames`、`aliases` 或“别名”；没有别名至少保留姓名。角色条目默认常驻，可用用户已有工具批量切换开关和开启方式。

预览仅收集符合写卡助手原协议的结果；这些协议由角色卡提供，插件不另写一套格式。

## 1.9.4 结果楼层隔离设计与验收

目标是仅隔离当前批次的结果楼层，继续复用原生候选回复、角色队列、恢复记录、原生生成流程和已有哈希工具。预设、命令、角色卡、世界书及上方消息照常参与生成与界面显示。手动开关控制只读纯文本展示及请求上下文排除；关闭后恢复原生渲染。

实现边界：一个结果正文节点的可撤销写入保护、一个消息容器观察器、固定数量的原生优先事件监听；酒馆助手的非流式与流式前端不得在受保护楼层运行。未选中候选仅保留数据，切页复用同一显示节点。指纹附在原生候选元数据中，不复制正文；保护期间校验已保存内容，发现变化停止派发并记入既有错误日志，关闭开关允许人工编辑及重新建立基线。关闭、切聊天、重置和卸载清理视图保护及自身监听。原生 `generate_interceptor` 仅从本次请求副本删除目标结果消息，不修改用户历史或任何原生隐藏标记。

工程范围为此功能及移除 1.9.3 的错误历史隐藏实现；采用局部功能替换，不重写队列或存储。ST-A0、ST-D5、ST-E5 路由快照 2026-08-18；基线 354 项测试通过。预算最多 18 个文件、1800 行变更，回退到 1.9.3。核对原生 SillyTavern 1.18.0 `51ad27f` 及 Tavern Helper 4.8.18 `2094779`、4.12.0 `40e4b72` 的渲染入口。运行中的同源扩展仍能主动访问聊天数据，本功能不声明跨插件权限沙盒。

最终自动检查：`npm run verify` 通过，34 个测试文件、364 项测试、118 个运行模块边界检查。用行为测试替换原来仅搜索源码字符串的静默模式测试，覆盖精确消息排除、关闭与切聊天、50/100 份元数据、原文变更、异步切聊天及监听清理。

隔离 SillyTavern 1.18.0 + 实际 Tavern Helper 4.8.18 + Chromium 153 验收通过，7 次合成模型请求，无真实模型费用。先验证首次结果和后续结果的流式、非流式生成代码均未执行；再分别写入 50/100 份约 1.2 万字符的候选，反复原生切页后保持三层消息、一个纯文本视图、一个渲染阻止标记，结果区 iframe 与代码块均为零，原文全部一致，原生事件监听总数在两种规模下均为 166。上方测试工作界面正常执行，隔离开关关闭后结果页恢复实际前端执行，重新打开则取消结果前端。酒馆助手流式渲染开启后也无法渲染受保护楼层。

刷新后 100 份原文及保护状态保留；390px 窄屏长中文正文无横向溢出。实际原生请求保留上方工作消息、生成命令、角色卡及世界书标记，排除结果内容。模拟旧候选原文变化后零新增模型请求，下载日志源中记录 `RESULT_CHANGED` 且不含正文。通过公开入口停用／重启后保护节点及全局拦截器清理、固定事件监听数量恢复正确。

测试区的酒馆助手外部更新检查出现网络告警，不影响上述实际 iframe 正反对照；4.12.0 仅核对源码入口，未在用户设备验收。本测试不把 50/100 份数据的存储成本当作零，也不宣称同源插件无法主动访问原文。

复跑新隔离用例：在安装本扩展与实际酒馆助手的隔离酒馆中运行 `SMOKE_ISOLATION_ONLY=1 ST_TEST_URL=http://127.0.0.1:18019 node scripts/smoke-role-batch.mjs`。普通完整回归仍使用原命令；添加 `SMOKE_ISOLATION=1` 会在普通回归后追加隔离验收。

联合验收：在同一实际酒馆助手宿主中，普通 19 次请求回归与隔离验收连续执行通过，共 23 次合成请求；包括空回复、流式失败、手动停止后重启、刷新续接、过期进度核对、名单增删和新隔离功能。普通流程单独执行的 19 次回归也通过。宿主脚本按角色文件重新定位测试卡并筛选列表，避免分页及刷新后序号变化；普通回归显式关闭隔离，隔离用例自行开启，避免沿用上次测试设置。

保留的验收问题：完整刷新恢复检查曾间歇出现任务完成记录与重新载入的候选原文不一致，导致重复派发或缺少已完成候选。最终联合验收通过，但尚未稳定复现并确定原因，不能据此认定该问题已修复。对照 1.9.3 在相同助手宿主的 19 次流程通过，暂不能确认问题归因。本次不扩大为队列／存储重写；用户设备的后台挂起与跨插件恢复仍需实际日志复核。

## 1.9.5 三页显示豁免与检测一致性

用户确认：三页豁免仅改变显示和渲染，旧角色卡仍不进入下一角色的模型请求。当前第 10 页时放行 9／10／11，切到 11 页后范围变为 10／11／12；首尾按已存在的候选及正在生成的新页计算。原生酒馆每次只挂载当前候选，前后页为可切换的数据，因此复用原生切页和助手的按楼层渲染／卸载，不创建三份缓存页面。取消 1.9.4 对当前正文的拦截与纯文本重画，开关只维护预览范围提示、请求排除和原文完整性保护。豁免不允许静默改写原文；主动编辑仍需先关闭隔离再重新建立校验基线。

具体修复：校验逐页读取当前绑定的正文，不再把选中索引变化本身当成内容改变；切页导致候选数组或元数据对象更换时，仍核对对应原文。请求拦截在异步校验前固定请求副本所对应的元数据，避免校验中切页后漏删目标结果。生成、恢复、重置传递相同的最小长度和结束标签选项，继续复用既有完整性判断；收到非空但不合格的正文写入 invalid 标记，恢复旧 complete 标记时也重新核对正文。

授权与范围：用户明确同意三页豁免及两处检测修复。各路径采用局部修复，复用原生候选、队列、名单、恢复存储和日志；不新增依赖，不更改候选正文存储，不实现本轮仅讨论的定点重答插件，不改既有标签启发式解析。A0 路由 code-quality-workflow，快照 2026-08-18、ST-A0；基线 f728a5d（1.9.4），自动检查 364 项通过。预算最多 16 个文件、1400 行，回退点为 1.9.4。新增用例先在旧实现上复现失败，再核对修复；当前自动检查 34 个文件、370 项测试及 118 个模块边界检查通过。
